## Установка

### Требования

- **Node.js** версии 16.x или выше
- **Visual Studio Code** версии 1.85 или выше
- **Roo Code** или **Roo Cline** расширение (для использования MCP-инструментов)

### Установка из VSIX файла

1. Откройте Visual Studio Code
2. Перейдите в раздел "Extensions" (Расширения)
3. Нажмите на три точки (...) → "Install from VSIX..."
4. Выберите файл `roo-trace-*.vsix`
5. Перезапустите VSCode

### Сборка из исходного кода

```bash
git clone https://github.com/your-repo/roo-trace.git
cd roo-trace
npm install
npm run compile
npm run package
```

### Первый запуск

При первом открытии проекта расширение автоматически:
- Запустит HTTP-сервер на порту 51234 (по умолчанию; может быть переопределён в `rooTrace.serverPort` в VS Code Settings). Актуальный порт сохраняется в `.rootrace/debug_port`
- Зарегистрирует MCP-сервер RooTrace
- Создаст конфигурационные файлы (`.roo/mcp.json`, `.rootrace/ai_debug_logs.json`, `.rootrace/ai_debug_config`, `.rootrace/debug_port`). Примечание: конфиг шифруется для безопасности; порт в открытом виде
- Создаст директорию `.rootrace/` и добавит её в `.gitignore`

Проверьте канал Output > AI Debugger для подтверждения запуска.

## Использование AI Debugger

### Обзор

AI Debugger использует научный метод для выявления и устранения багов. В версии 0.0.1 реализован **Железный мост** — система безотказной файловой синхронизации, которая гарантирует надежность и отсутствие потери данных.

### Интерфейс взаимодействия

AI Debugger использует интерактивные сообщения с кнопками:

- **"Я выполнил (Logs ready)"** - После запуска кода и воспроизведения ошибки
- **"Прочитать логи (кнопка)"** - Для явного разрешения чтения логов AI
- **"Разрешить авто-отладку (5 мин)"** - Для долгосрочного разрешения чтения логов
- **"Очистить сессию"** - Когда проблема решена и нужно завершить сессию
- **"Открыть дашборд"** - Для просмотра логов в реальном времени

**Важно:** 
- Чтение логов требует явного одобрения через кнопку (безопасность)
- Во время ожидания вы можете написать сообщение AI - оно будет иметь приоритет
- Одобрение действует 2 минуты (или 5 минут для авто-отладки)

### Научный метод отладки (9 фаз: 0-8)

0. **TODO List** - AI создает краткий список задач (макс. 5-7 слов на задачу, ADHD-friendly)
1. **Инициализация** - AI проверяет статус сервера RooTrace и тест записи/чтения
2. **Обнаружение сети** - AI обнаруживает порт из `.debug_port` и проверяет Docker bridge (`host.docker.internal` или `172.17.0.1`)
2.2. **Smoke Test** - AI отправляет тестовый лог из целевого окружения и проверяет его получение (обязательно перед Phase 3)
3. **Формирование гипотез** - AI формирует 3-5 проверяемых гипотез (H1-H5)
4. **Инъекция проб** - AI вставляет точки отладки с UUID-маркерами (после мета-когнитивной проверки)
5. **Ожидание действий пользователя** - Вы запускаете код и воспроизводите баг (или авто-отладка)
6. **Анализ логов** - AI собирает и анализирует логи (синхронизированные через Железный мост)
7. **Исправление** - AI предлагает и применяет исправление (цикл проверки)
8. **Очистка** - AI очищает сессию только после подтверждения

### Мета-когнитивное управление

Перед каждым изменением кода AI проводит внутреннюю проверку через экспертную панель:

- **Аналитик**: Проверяет scope переменных, импорты, экономию токенов, пустоту массивов
- **Критик**: Ищет места, где код упадет (импорты, scope, синтаксис, производительность)
- **Изобретатель**: Оптимизирует для лаконичности (The 5-Line Rule)
- **Профессор**: Проверяет соответствие стандартам, вредные привычки (`print()`), галлюцинации перевода
- **Скептик**: Проверяет гипотезы на основе данных (только после Phase 5)

Это предотвращает ошибки компиляции и улучшает качество проб.

### UUID-маркеры и автоматический Rollback

Каждая проба получает уникальный ID для точного удаления:

```javascript
// RooTrace [id: a1b2] Hypothesis H1: Checking variable value
try { fetch('http://localhost:51234/', { ... }) } catch(e) {}
// RooTrace [id: a1b2]: end
```

**Важно:** 
- Если инъекция пробы приводит к ошибке синтаксиса, файл автоматически откатывается
- Вы не увидите "красных" ошибок в терминале — система защищает ваш код
- Пробы следуют "The 5-Line Rule" — максимум 5-7 строк для чистоты кода
- Пробы включают метрики количества (`len(array)`, `is_empty`) для диагностики
- Пробы оптимизированы — не дублируют импорты, если они уже есть в файле

### Пример полного цикла

**Пользователь:** "У меня возникает ошибка при отправке формы"

**AI:** Формирует гипотезы (H1-H5) и вставляет пробы с UUID-маркерами

**Пользователь:** Запускает код, воспроизводит баг, нажимает "Продолжить"

**AI:** Анализирует логи (синхронизированные через Железный мост), находит проблему, предлагает исправление

**Пользователь:** Подтверждает исправление, проверяет, нажимает "Проблема устранена"

**AI:** Удаляет все пробы через UUID-маркеры, обнуляет логи, проект чист

### Надежность системы

- **Железный мост**: Файловые блокировки и `fs.watchFile` для безотказной синхронизации
- **Автоматический Rollback**: Защита от битых состояний файла
- **UUID-маркеры**: Точное удаление только вставленных проб

## Устранение неполадок

### Расширение не активируется

**Симптомы:**
- Канал "AI Debugger" отсутствует в Output Panel
- MCP сервер не регистрируется

**Решение:**
1. Выполните команду вручную: `Cmd+Shift+P` → "RooTrace: Start Server"
2. Проверьте Developer Console: Help → Toggle Developer Tools → Console
3. Убедитесь, что workspace folder открыт
4. Пересоберите расширение: `npm run compile && vsce package`

### MCP-инструменты недоступны

**Симптомы:**
- Ошибка `Tool does not exist on server` для `load_rule` или `get_problems`
- В списке доступных инструментов отсутствуют новые инструменты
- В `.roo/mcp.json` в `alwaysAllow` отсутствуют `load_rule` и `get_problems`

**Причина:**
Конфигурация MCP не обновляется автоматически после обновления расширения. Если расширение было установлено до добавления новых инструментов, они не будут в `alwaysAllow`.

**Решение (ВАЖНО - выполните ВСЕ шаги):**

1. **Обновите `.roo/mcp.json`** (если еще не обновлен):
   ```json
   {
     "mcpServers": {
       "roo-trace": {
         "command": "node",
         "args": ["/path/to/mcp-server.js"],
         "env": {
           "ROO_TRACE_WORKSPACE": "/path/to/workspace"
         },
         "alwaysAllow": [
           "read_runtime_logs",
           "get_debug_status",
           "clear_session",
           "inject_probes",
           "load_rule",
           "get_problems"
         ]
       }
     }
   }
   ```

2. **КРИТИЧЕСКИ ВАЖНО: Перезапустите MCP сервер в Roo Code:**
   - Откройте Roo Code панель
   - Нажмите на иконку ⚙️ в верхней навигации (MCP settings)
   - Найдите сервер "roo-trace" в списке
   - Нажмите кнопку 🔄 (Restart) рядом с сервером
   - **Это обязательно!** Roo Code не перечитывает конфигурацию автоматически

3. **Альтернатива:** Если кнопка Restart не помогает:
   - Перезапустите Roo Code полностью (закройте и откройте заново)
   - Или используйте команду: `Ctrl+Shift+P` → `RooTrace: Re-register MCP Server`
   - Затем перезапустите MCP сервер через UI (шаг 2)

**Проверка:**
После перезапуска MCP сервера проверьте:
1. В `.roo/mcp.json` в `alwaysAllow` присутствуют все инструменты
2. MCP сервер "roo-trace" показывает статус "Connected" в Roo Code UI
3. Инструменты `load_rule` и `get_problems` доступны в списке инструментов

**Примечание:** `alwaysAllow` влияет только на автоматическое одобрение инструментов. Видимость инструментов зависит от того, что MCP сервер их предоставляет. Если инструменты не видны после перезапуска, проверьте, что MCP сервер запущен и подключен.

### Логи не появляются в Dashboard

**Решение:**
1. Убедитесь, что HTTP-сервер запущен (проверьте Output > AI Debugger)
2. Проверьте файл `.rootrace/debug_port` в корне проекта
3. Убедитесь, что отладочный код отправляет POST-запросы на `http://localhost:51234/`
4. Проверьте права доступа к файлу `.rootrace/ai_debug_logs.json`
5. Проверьте логи проб в файле `~/.roo_probe_debug.log` (для Python)
6. Убедитесь, что пробы выполняются (проверьте консоль на наличие `[RooTrace Probe]` сообщений)

### Проблемы с Docker контейнерами

**Симптомы:**
- Пробы не отправляют логи из Docker контейнера
- Ошибки подключения к `localhost:51234` из контейнера

**Решение:**
1. Убедитесь, что инициализация хоста добавлена в начало файла (проверьте наличие `_rootrace_host` для Python или `rootraceHost` для Go)
2. Проверьте логи проб в `~/.roo_probe_debug.log` (для Python) - там должна быть информация об используемом URL
3. Если `host.docker.internal` недоступен, проверьте версию Docker (требуется Docker Desktop для Mac/Windows или Docker 20.10+ для Linux)
4. Установите переменную окружения `ROO_TRACE_HOST` вручную:
   ```bash
   # Определите IP хоста из контейнера
   export ROO_TRACE_HOST=$(ip route show default | awk '/default/ {print $3}')
   # Или используйте фиксированный IP шлюза (обычно 172.17.0.1)
   export ROO_TRACE_HOST=172.17.0.1
   ```
5. Для Linux: убедитесь, что Docker запущен с флагом `--add-host=host.docker.internal:host-gateway` или используйте переменную окружения

### Сервер не запускается

**Решение:**
1. Проверьте, что Node.js установлен и доступен в PATH
2. HTTP-сервер использует порт 51234 по умолчанию (может быть изменен через `rooTrace.serverPort` в VS Code Settings). Проверьте файл `.rootrace/debug_port` для актуального порта
3. Перезапустите VSCode
4. Проверьте логи в Output > AI Debugger

## Особенности работы с Python

### ⚠️ КРИТИЧЕСКИ ВАЖНО: Ограничения для Python файлов

**ЗАПРЕЩЕНО использовать `inject_probes` или `inject_multiple_probes` для Python файлов (.py)!**

Для Python файлов используйте **Block Rewrite метод** (`apply_diff`):
- Заменяйте всю функцию/блок целиком вместо точечной инъекции
- Это предотвращает ошибки отступов (IndentationError)
- Сохраняет структуру кода

### 🛡️ Требование резервной копии перед редактированием

Перед редактированием любого файла (включая Python) система требует создания резервной копии:

**Если проект в git репозитории:**
```bash
git add .
git commit -m "AI Debugger: Pre-instrumentation backup"
```

**Если проекта нет в git:**
```bash
cp file.py file.py.bak
```

Это требование безопасности для возможности отката изменений.

### Редактирование Python файлов

Роль "AI Debugger" может редактировать `.py` файлы через `apply_diff` (Block Rewrite). Инструмент `inject_probes` **запрещен** для Python.

### Важно для Python

- Используйте `apply_diff` для замены функций/блоков целиком
- Не используйте точечную инъекцию проб - это может привести к ошибкам отступов
- Проверка синтаксиса использует `python3 -m py_compile`
- Система автоматически проверяет наличие резервной копии перед редактированием

## Поддержка Docker

RooTrace автоматически определяет Docker окружение и настраивает пробы для работы как внутри контейнеров, так и на обычных машинах.

### Динамическое обнаружение сети (Phase 2)

Перед началом инструментации система автоматически:
1. **Обнаруживает порт**: Читает `.rootrace/debug_port` или `.debug_port` в корне проекта
2. **Определяет окружение**: Проверяет наличие Docker через `docker ps`
3. **Проверяет Docker bridge**: Выполняет `docker exec curl` для проверки доступности `host.docker.internal` или `172.17.0.1`
4. **Smoke Test (Phase 2.2)**: Отправляет тестовый лог из целевого окружения (Docker или локального) и проверяет его получение через `read_runtime_logs`
5. **STOP/GO**: Если smoke test не прошел, система не продолжает к инструментации и сообщает об ошибке

Это предотвращает трату времени и токенов на работу с неработающей сетью.

### Автоматическое определение окружения

Система автоматически определяет Docker окружение при первой инъекции пробы в файл:

- **Python (.py)**: В начало файла добавляется переменная `_rootrace_host`
- **Go (.go)**: В начало файла добавляется переменная `rootraceHost`

### Как это работает

1. **Определение Docker**: Система проверяет наличие файла `/.dockerenv` или строки "docker" в `/proc/self/cgroup`
2. **Определение хоста**: Используется следующая цепочка fallback:
   - Переменная окружения `ROO_TRACE_HOST` (если установлена)
   - `host.docker.internal` (если доступен в Docker)
   - Gateway IP (определяется через UDP соединение к 8.8.8.8:80)
   - `localhost` (по умолчанию)

### Пример для Python

```python
# RooTrace [init] Host detection - устанавливаем _rootrace_host для всех проб
try:
    import os, socket
    _rootrace_host = os.environ.get('ROO_TRACE_HOST')
    if not _rootrace_host:
        # ... логика определения Docker и хоста ...
    else:
        _rootrace_host = 'localhost'
except:
    _rootrace_host = 'localhost'
# RooTrace [init]: end
```

Пробы автоматически используют эту переменную:
```python
# Проба автоматически заменяет localhost на _rootrace_host
server_url = base_url.replace('localhost', _rootrace_host) if '_rootrace_host' in globals() else base_url
```

### Пример для Go

```go
// RooTrace [init] Host detection - устанавливаем rootraceHost для всех проб
var rootraceHost = func() string {
    if host := os.Getenv("ROO_TRACE_HOST"); host != "" {
        return host
    }
    // ... логика определения Docker и хоста ...
    return "localhost"
}()
// RooTrace [init]: end
```

Пробы автоматически используют эту переменную:
```go
serverURL := "http://localhost:51234/"
if rootraceHost != "" && strings.Contains(serverURL, "localhost") {
    serverURL = strings.Replace(serverURL, "localhost", rootraceHost, 1)
}
```

### Переопределение хоста через переменную окружения

Вы можете принудительно установить хост через переменную окружения:

```bash
# В Docker контейнере
export ROO_TRACE_HOST=172.17.0.1  # IP шлюза Docker

# Или на хосте
export ROO_TRACE_HOST=localhost
```

### Важные замечания

- **Автоматическая вставка**: Инициализация хоста добавляется автоматически при первой инъекции пробы - **не редактируйте её вручную**
- **Один раз на файл**: Инициализация добавляется только один раз в начало каждого файла
- **Автоматическая очистка**: При удалении всех проб инициализация хоста также удаляется
- **Dockerfile/docker-compose**: Система определяет Docker-проект по наличию `Dockerfile` или `docker-compose.yml` в корне проекта

## Советы по использованию

1. **Следуйте протоколу**: AI строго следует протоколу из 9 фаз (0-8), включая обязательный smoke test перед инструментацией
2. **Используйте кнопки**: Нажимайте кнопки в чате после выполнения инструкций
3. **Приоритет сообщений**: Во время ожидания вы можете написать сообщение AI
4. **Циклы проверки**: После исправления AI будет проверять решение в цикле
5. **Доверьтесь системе**: Железный мост гарантирует надежность — логи не потеряются
6. **Мета-когнитивная проверка**: AI автоматически проверяет код перед изменением через экспертную панель
7. **Правила гигиены**: Пробы следуют The 5-Line Rule, включают метрики количества, оптимизируют импорты
8. **Контроль языка**: AI использует правильную терминологию на вашем языке (русские термины при русском языке)

## Важные замечания

- **Динамический порт**: Система автоматически обнаруживает порт из `.debug_port` или использует `51234` по умолчанию
- **Динамический хост**: Для Docker автоматически определяется `host.docker.internal` или `172.17.0.1`, для локального окружения - `localhost`
- **Smoke Test**: Обязательная проверка соединения реальным тестовым логом перед началом инструментации (Phase 2.2)
- **MCP инструменты**: AI использует только инструменты RooTrace (get_debug_status, inject_probes, read_runtime_logs, clear_session, load_rule, get_problems)
- **Безотказность**: Система работает на уровне файловой системы, даже если VS Code зависнет
- **Чистота кода**: После отладки в коде не остается забытых `console.log` или закомментированных кусков
- **Директория .rootrace**: Все файлы конфигурации и логов хранятся в `.rootrace/` (автоматически добавлена в `.gitignore`)
- **Безопасность**: Чтение логов требует явного одобрения пользователя через кнопку в UI
- **Резервные копии**: Перед редактированием файлов требуется создание git commit или .bak копии
- **Python ограничения**: Для Python файлов используйте `apply_diff` (Block Rewrite), а не `inject_probes`
- **Docker поддержка**: Автоматическая поддержка Docker для Python и Go проектов - система определяет окружение и настраивает правильный хост
- **Языки**: Поддержка Python, Go, JavaScript, TypeScript, Java, Rust, C++, PHP, Ruby, C#, Swift, Kotlin и других
- **Английские промпты**: Система использует английские промпты (`ai-debugger-prompt.en.md`) для экономии токенов и лучшего следования инструкциям
- **Мета-когнитивное управление**: AI проводит внутреннюю проверку перед каждым изменением кода через экспертную панель
- **Правила гигиены кода**: The 5-Line Rule, метрики количества (`len()`, `is_empty`), оптимизация импортов, асинхронность
- **ADHD-специфика**: TODO list максимально краткий (макс. 5-7 слов на задачу) для легкого сканирования
- **Контроль галлюцинаций**: AI использует правильную терминологию на языке пользователя (русские термины при русском языке)
