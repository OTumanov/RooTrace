## 🎯 КЛАССИФИКАЦИЯ ЗАДАЧ ПО КРИТИЧНОСТИ

### 🔴 **КРИТИЧЕСКИЕ И БЛОКИРУЮЩИЕ**

Без исправления этих проблем система не может стабильно работать или представляет угрозу безопасности:

1. **Race condition в FileLock системе** (`file-lock-utils.ts`)
   - **Риск**: Deadlock, потеря данных, зависание VS Code
   - **Решение**: Атомарный AsyncMutex с гарантией FIFO
   - **Приоритет**: Немедленный

2. **Уязвимость шифрования** (`encryption-utils.ts`)
   - **Риск**: Компрометация зашифрованных логов, data breach
   - **Решение**: Запрет default ключа, генерация уникального ключа на workspace
   - **Приоритет**: Немедленный

3. **Синхронизация HTTP/MCP серверов** (`shared-log-storage.ts`)
   - **Риск**: Потеря логов при конкурентной записи
   - **Решение**: Версионирование логов (MVCC) с hash-валидацией
   - **Приоритет**: Немедленный

4. **Атомарная запись файлов** (отсутствует)
   - **Риск**: Коррупция файла при краше процесса
   - **Решение**: Паттерн write-tmp-rename с валидацией JSON
   - **Приоритет**: Высокий

### 🟠 **ВАЖНЫЕ, НО НЕ БЛОКИРУЮЩИЕ**

Улучшают архитектуру, производительность и поддержку, но не приводят к немедленному краху:

5. **Утечка памяти в SharedLogStorage**
   - **Риск**: Накопление watchers при перезапусках
   - **Решение**: `dispose()` метод, очистка ссылок
   - **Приоритет**: Высокий (после критических)

6. **Блокирующий JSON.stringify на больших логах**
   - **Риск**: Заморозка UI на 200-500ms
   - **Решение**: Асинхронная запись через streams, батчинг
   - **Приоритет**: Высокий

7. **Контроль доступа к логам (security token)**
   - **Риск**: Возможность переиспользования approval token
   - **Решение**: TTL, уникальные токены, гарантированное удаление
   - **Приоритет**: Средний

8. **Неправильная обработка Promise в MCP Handler**
   - **Риск**: Молчаливые сбои, undefined tools
   - **Решение**: Валидация, явные ошибки
   - **Приоритет**: Средний

9. **Расщепление extension.ts (God object)**
   - **Риск**: Сложность поддержки, тестирования
   - **Решение**: Модульная архитектура, DI
   - **Приоритет**: Средний

### 🟡 **ОПЦИОНАЛЬНЫЕ/КОСМЕТИЧЕСКИЕ**

Можно отложить без существенного ущерба для работы системы:

10. **Оптимизация priority queue (O(n) → O(log n))**
    - **Риск**: Снижение производительности при >1000 операций
    - **Решение**: Binary heap
    - **Приоритет**: Низкий

11. **Backpressure механизм для WebSocket**
    - **Риск**: Потеря сообщений при медленном consumer
    - **Решение**: Бафферизация, контроль скорости
    - **Приоритет**: Низкий

12. **Переписывание LLM промптов**
    - **Риск**: Снижение эффективности работы агента
    - **Решение**: Психологически корректные инструкции
    - **Приоритет**: Низкий

13. **Добавление операционных метрик**
    - **Риск**: Отсутствие observability
    - **Решение**: MetricsCollector, трассировка операций
    - **Приоритет**: Низкий
